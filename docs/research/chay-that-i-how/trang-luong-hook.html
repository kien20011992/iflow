Hook nhắc việc dở của i:flow chạy thế nào

Đang giảng: hook hooks/iflow-resume.sh, đăng ký trong hooks/hooks.json, plugin i bản 1.11.1.

Mỗi khi một phiên Claude Code bắt đầu, kể cả sau /clear hay sau khi hội thoại bị nén, script này lục thư mục docs/shape/ của repo tìm hồ sơ i:flow còn dở. Với mỗi hồ sơ dở, nó in cho Claude hai dòng: slice nào đang làm và việc tiếp theo là gì. Hồ sơ nào hỏng thì nó giấu việc tiếp theo đi và bảo sửa hồ sơ trước. Không có việc dở thì nó im lặng hoàn toàn.

Hai chữ dùng suốt trang. Hồ sơ (code gọi là dossier) là thư mục docs/shape/<tên>/ mà i:flow tạo khi bạn duyệt bảng chia việc. File chính của nó là shape.md, ghi trạng thái của cả chương trình. Slice là một phần việc nhỏ trong chương trình đó, mỗi slice có file riêng slice-NN-<tên>.md.

Ví dụ đi suốt trang

Hôm qua Lan dùng i:flow làm "Luồng đăng ký" trong repo shop, chia thành hai slice. Slice 01 (form đăng ký) đã xong. Slice 02 (gửi email xác nhận) đang làm dở thì Lan tắt máy. File shop/docs/shape/dang-ky/shape.md lúc đó có các dòng này:

5Hook đưa thư mục dang-ky/ cho checker kiểm, đọc mã thoátmở

Checker là script skills/flow/scripts/check-dossier.sh. Nó kiểm hồ sơ theo lối máy móc, không hiểu nội dung. Theo bảng trong CLAUDE.md, nó kiểm những điều sau:

  • Overall status: chỉ được là running hoặc done.
  • Current slice: phải khớp với hàng đang doing trong bảng.
  • Next action: không được rỗng hay là chữ giữ chỗ.
  • File phải có dấu iflow/2.
  • Mỗi hàng chưa retired phải có file slice-NN-*.md tương ứng.

Checker thoát với mã thoát (exit code, con số script trả về khi kết thúc): 0 là sạch, 1 là có lỗi. Hook dịch mã đó thành biến st với ba giá trị, xem ô rẽ nhánh ngay dưới.

hooks/iflow-resume.sh:44-62

  # st: 0 = checked and sound · 1 = checked and broken · 2 = cannot check.
  # Only exit 1 means "the dossier is wrong"; any other failure is the
  # checker's own, and blaming the dossier for it would be a false alarm.
  st=0
  out=""
  if [ -f "$checker" ]; then
    out=$(bash "$checker" "$(dirname "$f")" 2>&1); rc=$?
    case "$rc" in
      0) ;;
      1) st=1
         [ -z "$out" ] && out="check-dossier.sh reported a violation without output" ;;
      *) st=2
         [ -z "$unverified_why" ] &&
           unverified_why="check-dossier.sh itself failed (exit $rc) at $checker" ;;
    esac
  else
    st=2
    [ -z "$unverified_why" ] && unverified_why="no check-dossier.sh at $checker"
  fi

Vì sao chỉ mã 1 mới tính là hồ sơ hỏng

Theo chú thích trong file: checker có thể tự hỏng, ví dụ thiếu file hay lỗi cú pháp, và thoát với mã 2 hoặc 127. Lúc đó lỗi là của checker. Đổ cho hồ sơ là báo động giả, và sẽ làm Claude bỏ qua một hồ sơ hoàn toàn lành.

7In tên hồ sơ và dòng nhắc, hoặc cờ hỏng kèm lời checkermở

Gặp hồ sơ đầu tiên cần nhắc, hook in một dòng tiêu đề, chỉ một lần dù có mấy hồ sơ. Sau đó mỗi hồ sơ được in theo một trong hai cách:

  • Lành hoặc không kiểm được: in đường dẫn shape.md, rồi chép nguyên hai dòng Current slice: và Next action: từ file, thụt lề bốn dấu cách. Hai dòng này là dòng nhắc.
  • Hỏng: in đường dẫn kèm ⚠ BROKEN STATE, rồi từng dòng lỗi của checker. Dòng Next action: không được in.

Mỗi dòng chép từ repo bị cắt ở 200 ký tự bằng hàm capped.

hooks/iflow-resume.sh:25-40

# capped <prefix> — indent stdin and cap each line. Nothing this hook echoes
# out of a repo file may be unbounded: both the status lines and the checker's
# own messages quote field values back. ${#line} and ${line:0:N} count
# characters in a UTF-8 locale, which matters for the user's own language.
capped() {
  while IFS= read -r line; do
    [ -n "$line" ] || continue
    if [ "${#line}" -gt 200 ]; then line="${line:0:200} …[truncated]"; fi
    printf '%s%s\n' "$1" "$line"
  done
}

# pointers <shape.md> — its status lines, indented and capped
pointers() {
  grep -E '^(Current slice|Next action):' "$1" | capped '    '
}

  • Cắt ở 200 ký tự. Theo chú thích trong file: mọi chữ hook chép ra từ file trong repo phải có giới hạn. Một Next action dài cả trang sẽ chiếm chỗ trong ngữ cảnh của Claude ở mọi phiên.   • Dòng tiêu đề ghi "quoted verbatim from files in the repo". Tôi suy ra lý do: để Claude biết các dòng thụt lề là chữ chép từ file, không phải lời của hook. Repo không ghi lý do này.

Bảng chữ

Hook
Script mà Claude Code tự chạy khi một sự kiện xảy ra. Ở đây là hooks/iflow-resume.sh.
SessionStart
Sự kiện "phiên vừa bắt đầu" của Claude Code, gồm năm kiểu: startup, resume, clear, compact, fork.
Hồ sơ (dossier)
Thư mục docs/shape/<tên>/ do i:flow tạo khi bảng slice được duyệt. File chính là shape.md.
Slice
Một phần việc nhỏ trong chương trình của i:flow, có file slice-NN-<tên>.md và một hàng trong bảng của shape.md.
Dấu iflow/2
Dòng <!-- generated-by: iflow/2 --> trong shape.md. Có nó thì hook mới coi file là hồ sơ.
Dòng nhắc
Hai dòng Current slice: và Next action: mà hook chép nguyên từ shape.md.
Checker
Script skills/flow/scripts/check-dossier.sh, kiểm máy móc xem hồ sơ có tự mâu thuẫn không.
Mã thoát (exit code)
Con số một script trả về khi kết thúc. Với checker, 0 là sạch và 1 là có lỗi.
Fail-closed
Nghi ngờ thì chặn. Ở đây: hồ sơ hỏng thì không cho Next action ra lệnh.
